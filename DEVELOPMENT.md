# Developing stanimal

This is the maintainer's guide: how the repository is laid out, how to build and
test it, and the traps that have bitten before. If you are *using* the package
rather than changing it, read `AGENTS.md` instead.

## Layout

- `package/` is the R package. `README.md` and `examples/` sit outside it, so they
  are not in the built tarball.
- `package/R/` — one file per concern: `lmm_animal.R` (animal models and the
  `Y`/`X`/`A` validation), `lm_phen_cov.R`, `lmm_animal_gibbs.R`,
  `animal_design.R`, `makeA.R`, `genomic_relationship.R`, `size_shape.R`
  (`pc1_variance_share()`, `size_shape()`, `back_transform()`), `random_covariance.R`,
  `scree.R` (`scree_eigenvalues()`, `suggest_n_factors()`, `plot.scree()`),
  `fit_draws.R` (draw reshaping and `draws_mean()`), `plots.R`, `utils.R`
  (validators), `cmdstan_support.r` (compilation, caching and the sampler call).
- `package/inst/stan/` — one Stan program per model:

| file | model |
|---|---|
| `animalModelUni.stan` | univariate, `parametrization = "variance"` |
| `animalModelUniH2.stan` | univariate, beta prior on h2 |
| `animalModelG.stan` | multivariate unstructured `G` and `E` |
| `animalModelGFactor.stan` | sparse factor `G` |
| `animalModelGSharedFactor.stan` | shared factors for `G` and `E` |
| `phenotypicModel.stan` | unstructured `P` |
| `phenotypicModelFactor.stan` | sparse factor `P` |

The animal models never see `A`: they take its eigendecomposition (`Q`,
`lambda`, ascending) as data. `.animal_relationship()` in `R/utils.R` builds the
pair once per fit, or validates a caller's `eigen_A`, and `lmm_animal()` and
`lmm_animal_laplace()` both go through it. Keep the ascending order (Stan's
`eigenvectors_sym` convention): it is what keeps fits bit-identical to versions
that decomposed `A` in Stan, which `test-eigen-A.R` checks against a model
written the old way. A custom `model_file` also receives `A`, since older
custom models declare it.

- `examples/*.R` are runnable scripts that write figures to `examples/figures/`
  (gitignored). `examples/README.md` indexes them.

`plan.md` is the working roadmap: incomplete trait records, breeding values and
LOO first, then evolutionary analysis of `G`, then the locus-effect models. It
lives on the **`roadmap` branch** rather than on `master`, so someone browsing the
repository is not presented with an internal plan. Read it with
`git checkout roadmap`, or `git show roadmap:plan.md` without switching.

## Commands

```sh
# tests (testthat edition 3, runs in parallel)
Rscript -e 'testthat::test_local("package", filter="model-P", reporter="summary")'
# documentation
(cd package && Rscript -e 'roxygen2::roxygenise(".")')
# build then check outside the checkout; checking the directory directly fails
(
  repo="$(pwd)"
  check_dir="$(mktemp -d "${TMPDIR:-/tmp}/stanimal-check.XXXXXX")"
  cd "$check_dir" &&
    R CMD build "$repo/package" &&
    R CMD check --no-tests --no-manual --no-build-vignettes stanimal_*.tar.gz
)
# examples call library(stanimal), so reinstall after changing R/ or inst/stan
R CMD INSTALL package
```

`R CMD check package/` fails before checking because the source `DESCRIPTION`
carries only `Authors@R`; the `Author:` and `Maintainer:` fields that check
requires are generated by `R CMD build`. Always build the tarball first.
The command above leaves the tarball and check results in a new temporary
directory, not the repository; the check output identifies their location.

`R CMD check` must stay at `Status: OK`.

## Testing

- Tests skip without CmdStan (`skip_if_no_cmdstan()`); rstan-only tests are
  skipped with `STANIMAL_SKIP_RSTAN=true`.
- Fits in tests are small (`iter` 200–1200, two chains) and check convergence with
  `expect_clean_fit()`, which allows `Rhat < 1.05` and no divergences.
- **Calibrate tolerances; do not guess.** Measure the actual error of the
  configuration, then set roughly twice it. Loose absolute bounds
  (`expect_lt(max(abs(P - truth)), 1.2)`) hid a real scale bug for weeks.
- Compare covariances on the **correlation scale** and relative to the best
  rank-`k` approximation. An absolute RMSE on entries of ~1e-3 is meaningless.
- `test-readme.R` executes every R block in the root `README.md`, but it **skips
  inside the built tarball** (the README is not in the package), so a green
  `R CMD check` says nothing about the README. Run it from a checkout with
  `filter="readme"`.
- Those README blocks run **sequentially in one shared environment**, seeded with
  fixtures from `readme_context()` (`Y` has 2 traits, plus `X`, `A`, `dat`,
  `log_traits`, `pedigree`, ...). A snippet must not clobber a name a later one
  needs, and must not ask for more factors than the fixture has traits.

## Documentation

- Roxygen markdown is **off** (no `Roxygen:` field in `DESCRIPTION`). Use
  `\code{}` and `\strong{}`, not backticks or `**bold**`.
- Escape prose `%` as `\%`. An unescaped `%` comments out the rest of the Rd line
  and the file fails to parse, with errors that point at unrelated lines.
- `ls("package:stanimal")` is the exported surface; internal helpers start with a
  dot and are used through `stanimal:::...` in tests.

## Packaging

- `.gitignore` does not control the tarball; `.Rbuildignore` does. Compiled Stan
  executables (cmdstanr and rstan write them next to the `.stan` sources) are
  excluded there — without that rule `R CMD check` reports the package contains
  executables.
- Compiled models are cached in `stan_cache_dir()`, keyed by a hash of the Stan
  code, so editing a `.stan` file recompiles automatically. After a CmdStan
  upgrade call `stanimal_clear_cache()`.

## Traps that have already cost time

- **cmdstanr output names collide under a shared random state.** Files are
  named from the model, the minute, the PID and one `runif()`, so two fits of
  one model after the same `set.seed()` within a minute share a CSV: the first
  fit silently reads the second's draws, and collecting it deletes the
  second's files. `.unique_output()` in `R/cmdstan_support.r` gives every run
  a `tempfile()`-based `output_basename`; keep it on every new call into
  cmdstanr that returns a fit the user keeps (`test-cstan.R` reproduces the
  collision). Not on `$laplace()`: released cmdstanr 0.9.0 reuses the
  basename for its internal mode file and CmdStan refuses the run, a failure
  the development cmdstanr does not show — test such changes against the
  CRAN cmdstanr.

- **`quad_form_diag(P_std, y_sd)` with a data-derived scale pins the diagonal.**
  In a factor model with `communality + uniqueness = 1`, the covariance's diagonal
  then equals the *marginal* variance while the likelihood is on residuals, so the
  sampler inflates the correlations to compensate. `phenotypicModelFactor.stan`
  needed a free `s_P`. There is a regression test asserting that `sigma_P` tracks
  the residual SD, not `sd(Y)`.
- **A shared `init` hides multimodality.** Passing `init = 0` made all chains
  start at the same point, so `communality` looked perfectly converged on a
  posterior with two modes. Each chain now draws its own start, from
  U(-1, 1) (`init = 1` in `cstan()`, `init_r = 1` for rstan). Don't widen it
  back to the engines' U(-2, 2): with 35 traits the correlation factor starts
  nearly singular, the step size collapses to ~1e-21 in warmup and the chains
  never move (seen in `examples/phenotypic_covariance.R`).
- **Factor summaries are rotation-dependent.** `loadings` and `factor_magnitude`
  are only pinned by the prior, so a poor `Rhat` there is not a failure. The
  exception is a bimodal `communality`, which is real.
- **Prior plots once compared against the wrong prior.** The fit now records its
  configuration and the plotting helpers reproduce it; factor fits and
  `model_file` fits error instead of guessing.
- **A redundant factor direction is not free.** `n_factors` above what the data
  support gives bimodal communalities rather than a better covariance.
- **rstan reads a one-element R vector as a scalar.** Data declared `array[n] int`
  with `n == 1` then fails with `mismatch in number dimensions declared and
  found`, which only shows up in the complete-data case where there is a single
  pattern. Pass such indices through `as.array()`. cmdstanr does not need it, so
  a cmdstanr-only test run will not catch it.
- **A large local in `generated quantities` is a saved quantity.** Declaring the
  rotated response there to compute `log_lik` wrote an `N x K` matrix per draw,
  and its `Ys[1]...Ys[N]` names broke `fit_draws()`'s trait inference, which then
  named the fit's single component `beta`. Keep it inside the `{ }` block that
  computes `log_lik`.
- **README blocks share one environment.** A snippet that reassigns `Y`, `dat` or
  `A` changes what every later snippet sees, so a new block should use its own
  names. `test-readme.R` catches it, but only after the whole file has run.
- **`S3method()` for a generic in a Suggests package fails at load.** R looks the
  generic up in the namespace and dies with `object 'loo' not found` if it is not
  imported. Register the method in `.onLoad` instead, with a
  `setHook(packageEvent("loo", "onLoad"))` for the case where the suggested
  package loads afterwards; `NAMESPACE` must then carry no `S3method()` entry.
  Note that `pkgload::load_all()` does not run `.onLoad`, so a test of the
  dispatch has to call it.
- **An intermittent `fit_loo()` failure in the parallel suite.** Seen twice in
  about fifteen full runs, both times in a different test (`test-loo.R`, then the
  WAIC test) and never when that file ran alone. The first occurrence reported
  that the fit does not report `log_lik`, which hid the real error: `fit_loo()`
  used to wrap the extraction in `tryCatch`. It now asks the fit which variables
  it holds (`metadata()$stan_variables` for CmdStan, the `model_pars` slot for
  rstan), and the second occurrence therefore surfaced the actual failure —
  `read_cmdstan_csv(): File does not exist:
  .../model_XXXX-YYYYMMDDhhmm-01-xxxxxx.csv`. That is the sampler's output file
  missing, not a missing `log_lik`: the CmdStan process did not finish writing.
  Both times another heavy CmdStan job was sampling in the same machine while the
  suite's twelve parallel workers ran (an example script fitting five models, or
  a long run left going), and both times the affected test passed on its own
  immediately afterwards. Treat it as resource contention — do not sample in
  parallel with the suite — and check `filter="loo"` first if it recurs.
- **`kronecker()` order does not match `vec()` of an individuals by traits
  response.** `vec(Y)` of an `N` by `K` matrix stacks the traits of every
  individual first, so its covariance is `kronecker(G, A)`, while
  `kronecker(A, G)` describes a `K` by `N` vector — the traits of one individual
  together. Writing the wrong one in a reference formula does not fail loudly:
  it produces the right *set* of numbers in the wrong order, so a test compares
  plausible values and fails on ordering alone. The reference formulas in
  `test-breeding-values.R` draw from `kronecker(A, G)` as a `K` by `N` vector
  and transpose it, and use `kronecker(G, A)` for the response as passed, with a
  comment saying which is which.

## Known gaps

- **`blend_A` is a flag where a weight belongs.** It is a logical: `TRUE`
  replaces `A` with `0.99 * A + 0.01 * I` in the `if (blend_A)` branch of
  `R/lmm_animal.R`, and `FALSE` leaves it alone. How much regularisation `A`
  needs is a property of the data rather than a yes or no question. A GRM built
  from a few hundred markers needs well above 0.01 before it is safely positive
  definite, while a large pedigree with a couple of duplicated genotypes needs
  far less, so the same constant either leaves the matrix near singular or moves
  a well-conditioned pedigree further from the truth than necessary. Let the
  argument take a logical or a number in `[0, 1)`, defaulting to `0` so nothing
  changes for existing calls, with `TRUE` read as `0.01` so the documented
  spelling keeps working and `0` leaving `A` alone. Exclude `1` rather than
  reading it as the identity, and warn above `0.2`, because at that weight the
  off-diagonals of `A` are already shrunk by a fifth and the blending has stopped
  being a repair for a singular matrix and become a change to the relationships
  the model is there to estimate. These have to move together: the signature and
  the `@param blend_A` text in `R/lmm_animal.R`, the `.check_flag()` call near
  the start of the body (which has to branch on `is.logical()` and send the rest
  to `.check_in_range(0, 1, open_high = TRUE)`, since neither validator accepts
  both kinds), the `if (blend_A)` branch, the warning itself, the error that
  tells a user to set `blend_A = TRUE` when `A` is not positive definite, the two
  validation tests in `tests/testthat/test-validation.R` that pass `NA` and
  `"yes"`, and the Methods text of the manuscript, which states the 0.99 and 0.01
  numbers as fixed.

## Style

`snake_case`. Argument names are backticked in error messages, and every `stop()`
and `warning()` passes `call. = FALSE`. Shared validators live in `utils.R`
(`.check_count`, `.check_positive`, `.check_flag`, `.check_whole`,
`.check_in_range`, `.check_beta_prior`); `%||%` is available. Comments explain
why a choice was made, not what the line does — the Stan files carry most of the
reasoning for the models.
